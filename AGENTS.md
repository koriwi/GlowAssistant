# Collaboration preferences

- Keep responses short, information-dense, and easy to scan. No walls of text.
- The user wants close control over scope and decisions. Do only the work explicitly requested; do not start unsolicited coding, refactors, or features.
- For broad or ambiguous requests, briefly outline the proposed scope and clarify consequential choices before implementing. Resolve routine details within agreed scope without repeated approval requests.
- Prefer simple, readable solutions. Avoid premature optimization, speculative abstractions, and unnecessary dependencies.
- Add comments only when the reason or behavior would otherwise be unclear. Keep them short; fragments are fine. Do not narrate obvious code.

- Integration reads HA registry/state snapshots, never HA MCP or a long-lived HA token. It uses HA's exposed-entity settings minus optional exclusions. Action requests currently run service → target_scope → area/target resolution → capability prefilter → parameter detection → required/selected field extraction → action plan/execution → reply. target_scope classifies entities (specific arealess/room-independent targets), entities_implied_area (one speaker area), entities_explicit_area (one explicit area), areas (one or more explicit areas without specific entities), implied_area (speaker area without specific entities), or unsure; text and number fields are extracted from HA selectors; HA executes live actions and benchmark.py always uses dry_run=True. For areas, one action_areas Choice selects every area at or above the effective cutoff from action_area_probability_threshold; these areas are final targets, without entity selection. For implied_area, use the supplied speaker area directly with no area/entity model calls. For entities_explicit_area, action_areas uses the unique highest probability (not the multi-area threshold), then filters candidates by domain and that area. For entities_implied_area, use speaker context to filter by domain and area without another area model call. For arealess entities, filter only by domain, including assigned/unassigned entities. The three entity paths use one action_entities Choice and retain every entity at or above the effective cutoff from action_entity_probability_threshold. Both probability thresholds default to 0.15 and have independent benchmark flags --action-area-threshold / --action-entity-threshold. none never overrides retained real options in multi-selection; ties or highest none in single-area selection stop. Empty selections and area/domain mismatches never broaden the search. Return the selected action's complete HA metadata under action_metadata and in the native service trace result; retain it with benchmark.py --json and native debug cards, and log it at DEBUG in conversation.py. Default benchmark output is compact and shows the action, speaker room, target type, area filter, candidate counts, targets, confidence and timings. Full option probabilities remain available in native debug cards and --json. Text and numeric values are extracted before action_calls groups explicit entity IDs by supported parameter subsets. HA passes an executor callback; the core invokes it only when dry_run=False. Required fields must be present and supported; broad target selectors cannot be supplied as parameters. HA rechecks current exposure and exclusions before each blocking service call and preserves the Assist context. Calls are sequential, never automatically retried, and stop after the first failure. Record each call and completed/partial/unconfirmed/not_sent outcomes. Successful commands/plans reply exactly ok by default. With Answer enable=true, send actual execution outcomes and prevent claims that dry-run plans executed. A post-execution reply failure uses answer_error_reply and reports that the command was already accepted. After successful target resolution, pass the actual selected entity members (all domain/area members for area targets; only selected IDs for entity targets) to parameter detection. Before building choices, flatten HA fields and apply declared filter.supported_features and filter.attribute rules against every resolved target, retaining a field when at least one resolved target supports it (matching HA field visibility). Record supported_entity_ids and unsupported_entity_ids per field under parameter_capabilities.field_support; future extraction/execution must respect those per-field target subsets rather than treating every offered field as supported by every target. Feature masks and allowed attribute values use HA semantics within each entity; cross-entity policy is any_resolved_target, not intersection. Missing/unknown capabilities or unsupported filter rules do not establish support. Unfiltered fields remain. Optional parameter detection runs with the resolved target included and uses one Choice question over optional fields plus none, flattening nested UI groups. Required fields remain separate. Keep each actual field at or above the effective cutoff derived from parameter_probability_threshold (default 0.15); ignore overall confidence and never let none override retained parameters. No optional fields means no extra call. Required fields are listed automatically without a model choice. Capability removals are labeled unsupported for selected targets; --json retains full probabilities. Prompt and probability threshold are under Decider; benchmark.py has --parameter-threshold, independent of --confidence. For target_scope, supply optional speaker_area to AgentEngine.process. Arealess means room-independent, not a missing HA area assignment or an omitted room name; a unique device name alone is insufficient. - All multi-select Choice selectors normalize the configured threshold with probability_cutoff in validation.py: effective cutoff = configured threshold / max(1, real option count). Exclude none/unsure first. Two real options halve the configured cutoff; three divide it by three. Apply this to action areas/entities, query targets, optional parameters and text words, with inclusive p >= effective cutoff. At threshold 1, uniformly distributed real options survive; threshold 0 retains zero-probability real options too. Defaults and flag names remain unchanged. Single-choice confidence and unique-highest area selection do not normalize. Debug includes probability_threshold (configured), real_option_count and effective_probability_threshold; CLI prints the calculation and effective drop reason. Keep the concern comment at the shared calculation: extra irrelevant options lower the cutoff too and can admit weak matches.
